# Warcraft III Cooperative Campaigns

将《魔兽争霸 III》的经典单人战役重制为可通过局域网等方式游玩的多人合作地图，并在尽可能保留原版剧情、地形、演出、任务流程和整体节奏的前提下，统一适配《冰封王座》的规则与内容。

项目地址：<https://gitlab.qunhequnhe.com/shenshi/coop>

## 项目目标

- 以原汁原味为首要原则。多人化所需的出生点、控制权、资源、任务和失败条件改动，不应无故改变原版关卡体验。
- 玩家槽位优先映射到原版已有阵营：玩家 1 保留原可玩阵营，后续玩家优先接管可持续参与的友方 AI 阵营；只在进入地图时判定一次，活跃真人停用该阵营 AI，正在游戏的电脑槽沿用原版 AI。空槽或未加入能否运行原版 AI 必须逐关在目标客户端验证，不能仅调用 `SetPlayerController` 后视为电脑。开局后不处理真人中途退出或断线。没有合适友军且单关明确批准时，才可拆分原玩家阵营。
- 将所有关卡完整适配到《冰封王座》的规则与数据体系，包括经济与人口机制、攻击与护甲类型及其伤害关系，以及单位、英雄、技能、科技和物品数据；维修费只是其中一项代表性差异。
- 必须兼容经典版 1.24e-1.27b；在不破坏该兼容基线的前提下，尽可能兼容 1.31。
- 不以 2.0 及后续版本为目标平台。后续版本若能直接运行属于额外收益，不得为此牺牲经典版兼容性。

## 制作方法

单关必须按[多人战役地图制作工作流](docs/MAP_PRODUCTION_WORKFLOW.md)依次推进：先只读检查官方战役文件并形成原版机制清单，再由项目负责人逐项确认多人适配、额外机制、最终目标和验收标准；之后才按固定目标做一次轻量社区检索。若已有作品满足全部条件则直接采用；若找到基本符合且仅需很少局部修改的作品，则与官方原图做简要成本比较；否则社区路线立即结束，只评估官方原图。路线由负责人选定后再细化、开发、验收和发布。

社区检索固定检查一个主要社区来源和一次独立跨站搜索，默认上限为 15 分钟且不延长。只保留关卡、合作人数与阵营分工、核心玩法和兼容范围均基本吻合，剩余差异明确且局部的轻改候选；其他命中合并记录关键排除理由，不下载、不排名、不深查。完成门和记录模板见[底图来源调查与决策流程](docs/SOURCE_EVALUATION.md)。

## 开发环境准备

克隆仓库后，开发者需要自行合法取得《魔兽争霸 III：冰封王座》游戏本体及对应的 World Editor，并放入 `game/` 目录。仓库不会提供游戏安装文件、压缩包、MPQ/CASC 数据或其他受版权保护的原始资源；`game/` 下除说明文件外的所有内容均已被 Git 忽略。

当前开发与验证需要相互隔离的经典版 1.24e 和 1.31 环境。建议目录结构及完整性要求见 [`game/README.md`](game/README.md)，详细的数据用途与版本要求见[游戏数据需求](docs/GAME_DATA.md)。

## 预期交付形式

战役关卡将以独立的 `.w3m` / `.w3x` 多人地图发布，而不是只提供单人自定义战役 `.w3n`。这样玩家可以在经典客户端的局域网或自定义游戏中逐关创建房间。

每一关至少应包含：

- 明确的玩家槽位与合作人数；
- 多人一致的任务、过场、胜利和失败状态；
- 合理的单位控制、资源与人口规则；
- 跨关英雄状态或替代性的存档/读取方案（仅在原关卡需要时）；
- 已验证的支持版本、已知问题和第三方来源说明。

## 内容与版权

本仓库不会提交游戏安装文件、原始 MPQ/CASC 数据或未经许可的第三方作品。引入社区地图前必须确认作者、来源、许可/授权状态和修改范围；基于官方战役制作的成果也应避免分发非必要的原始资源。仓库许可将在底图来源与可分发范围明确后再确定。
