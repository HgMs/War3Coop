# 底图来源调查与决策流程

社区地图站点、通用检索方法和跨关候选索引见[社区合作战役来源与候选](COMMUNITY_SOURCES.md)。本文细化[多人战役地图制作工作流](MAP_PRODUCTION_WORKFLOW.md)的第 3、4 阶段。目标是尽快发现可以直接复用或只需少量修改的作品，不是证明“互联网绝对不存在”或建立完整社区档案。检索记录只需说明查过哪里、如何查、找到哪些近似候选，以及为什么停止。

## 不可跳过的顺序

每一关必须按以下顺序推进：

1. **确认需求基线已冻结**：按 `docs/ORIGINAL_COOP_MECHANICS.md` 检查可追溯的官方原版，由负责人逐项决定保留、修改、移除或是否新增；确认文件中无 `待决定` 和影响验收的 `待核实`，并已记录负责人、日期和“目标与验收标准已确认”。再在关卡 `README.md` 摘要写明合作人数和模式、精确的“原版阵营 -> 玩家槽位”映射、真人/电脑/空槽的 AI 回退、原版还原要求、兼容目标、许可要求及该关特殊验收项。不得用搜索结果反推或静默改变标准。
2. **做一次聚焦检索**：建立该关的 `COMMUNITY_SEARCH.md`，默认上限为 30 分钟；已有高价值系列或多个近似命中时可延长至 60 分钟。检查一个主要社区来源和一次独立跨站搜索，记录实际检索式、近似候选和简要排除依据。
3. **先做网页粗筛**：把结果分为 `可直接采用候选 / 近似候选 / 明显偏离 / 无正向信号`。只有前两类继续核验；后两类不追完整版本链、镜像链或文件细节。
4. **按优先级核验**：先核验最可能直接采用或剩余改动最少的一个候选。只有首选被证伪时才递补次选；满足全部条件则执行直接采用分支并立即停止检索。
5. **结束检索**：首选核验完成，或聚焦检索未发现近似候选时即可结束第 3 阶段。结论写成“发现近似候选”或“本次聚焦检索未发现近似候选”，不要求排除互联网中的每一个未知文件。
6. **由负责人作出底图决策**：有近似候选时，与官方原图按同一工作分解比较；没有近似候选时，记录社区路线不成立，只评估官方原图。负责人明确确认路线后才可制作。

在第 6 步前，仅允许网页调查、只读地图检查和为消除关键不确定性而做的隔离验证；不得开始成品地图实现。已经提前形成的实验或 Alpha 可以保留，但在补齐证据门前不得继续扩展或进入发布流程。

## 粗筛与候选下载门

先使用发布页、作者说明、开发日志、版本历史和评论判断与最终目标的差距：

- 已有网页证据证明硬条件失败或大幅偏离最终目标时，记录关键证据、日期和链接后排除，不要求下载地图。
- 只有网页信息提供至少一项与目标直接相关的正向信号，例如正确关卡与合作人数、接近的阵营分工、原版还原取向或目标版本支持，才可能进入近似候选短名单。
- 纯标题命中、无说明转载、来源不明文件或只有“多人”标签的条目，若没有上述正向信号，记为 `无正向信号` 后结束；信息不足本身不构成下载理由，也不阻塞检索。
- 只有短名单首选接近最终目标、来源与取得方式合规，并且已经写明一个会改变采用或改造路线的文件级问题时，才下载地图。次选仅在首选被证伪后递补。
- 下载后只读检查，记录文件名、版本、来源和 SHA-256；不执行内嵌脚本，不提交未经许可的第三方二进制。

只有短名单候选需要按 `ORIGINAL_COOP_MECHANICS.md` 的稳定编号记录 `满足 / 不满足 / 未知`。明显偏离项只记录足以排除的关键差距。

## 每关必须保存的记录

### `ORIGINAL_COOP_MECHANICS.md`

在社区检索和底图决策前，以官方原版为只读基线完成。至少包含：

- 原版来源、版本、文件名、SHA-256 和静态检查证据；
- 所有会受多人化影响的原版机制，以及原版缺失但合作版必须决定的生命周期机制；
- 每项机制的稳定编号、原版事实、多人化关注点和负责人决定；
- 对修改、新增和移除项的目标行为、原因、影响范围与后续验收入口。

详细收录边界、决策值和模板见[原版多人化机制盘点规范](ORIGINAL_COOP_MECHANICS.md)。

### `COMMUNITY_SEARCH.md`

至少包含：

- 检索负责人、日期和实际投入时间；
- 本关预先定义的硬条件；
- 主要社区入口和一次独立跨站搜索所用的原样检索式；
- 进入短名单的候选、排序理由及其首发页；
- 明显偏离项的关键排除事实；同类结果可合并记录，不要求枚举全部镜像和转载；
- 短名单候选的状态：待核实 / 可直接采用 / 可少量修改 / 不符合 / 当前不可取得；
- 停止原因：已找到直接采用项、已选出最高优先级近似候选，或本次聚焦检索未发现近似候选。

搜索结果页会变化。记录应保留稳定条目链接和关键字段；允许保存不含第三方二进制的页面快照、截图或摘录，并注明取得日期。

### `SOURCE_EVALUATION.md`

至少包含：

- 短名单候选的硬条件核验；辅助评分按需使用，不是必填项；
- 入围成本比较的社区候选及选择理由；
- 社区候选路线与官方原图路线的同口径工作量估算；
- 若实际下载，记录地图文件名、SHA-256、来源、解析报告和实际验证版本；
- 假设、不确定性、失败风险、许可状态和未计入事项；
- 决策日期、结论、复核人，以及触发重新评估的条件。
- 负责人对执行路线的明确确认；没有确认时结论只能是“待决定”，不得开始成品制作。

全局 `COMMUNITY_SOURCES.md` 只能证明项目知道哪些来源，不能替代单关检索记录。

## 聚焦检索完成门

以下条件全部满足即可结束检索：

1. **最小覆盖**：至少检查一个主要社区来源，并执行一次独立跨站搜索。可以使用英文关卡名、章节代号或常用译名与 `co-op`、`2P`、`3P`、`multiplayer` 等高相关玩法词组合；不要求穷举所有名称和站点。
2. **结果分层**：把有意义的命中分为直接采用候选、近似候选、明显偏离或无正向信号。同类镜像和转载可合并记录。
3. **短名单闭环**：只需对最高优先级近似候选消除会影响采用或路线选择的关键未知项。次选候选在首选仍可行时不要求下载或深查。
4. **停止原因明确**：记录已找到直接采用项、已完成首选近似候选核验，或在默认时间预算内未发现近似候选。

只有存在明确正向信号、仍合理可能只需少量修改的候选才会阻塞。没有说明的标题命中、来源不明文件和纯转载不因“未知”而阻塞。结论必须限定为本次检索范围，不得写成“社区没有这种地图”。若检索结束超过 30 天才进入制作，只需快速复跑原检索式并检查已知项目是否更新。

## 候选硬条件与辅助评分

直接采用的候选必须同时满足该关已定义的功能要求、`1.24e-1.27b` 兼容要求、可审计/可维护要求，以及预定交付方式所需的许可要求。若只把原作者发布页、版本和哈希作为最终结果，应核验该发布页允许用户正常取得；若要把地图收入仓库或另行分发，则必须有相应再分发许可。基于候选修改还必须有改编许可。授权清晰度为 0 或地图无法审计时，不得进入仓库；总分不能抵消硬条件失败。

短名单中出现多个看起来同样接近的候选时，可以按 0–3 分辅助排序；只有一个明显首选时无需评分：

| 维度 | 0 分 | 3 分 |
| --- | --- | --- |
| 原版还原度 | 大幅重做 | 仅有合作必需改动 |
| 经典兼容性 | 依赖 Reforged/后期 API | 已验证 1.24e-1.27b |
| 可维护性 | 受保护、脚本不可读 | 可编辑、结构清晰 |
| 完整性 | 核心流程缺失/易卡关 | 主支线及演出完整 |
| 授权清晰度 | 来源或许可不明 | 作者明确允许修改和分发 |
| 改造成本 | 接近重做 | 少量可审计修改 |

## 成本比较门

只有存在近似社区候选时才比较两条路线。比较至少覆盖下列相同工作包，不能只比较文件大小、评分总分或已经投入的沉没成本：

| 工作包 | 应记录的证据示例 |
| --- | --- |
| 取得与授权 | 首发页、作者声明、许可文本、联系结果、可分发边界 |
| 格式与版本兼容 | 地图格式、编辑器版本、目标客户端/API 差异、降级工作 |
| 原版还原 | 地形/单位/对象/任务/对白/波次/过场差异清单 |
| 多人机制 | 原版阵营到玩家槽的精确映射、真人/电脑/空槽 AI 回退、出生、控制权、资源人口、任务同步、离开处理 |
| 脚本与数据维护 | 脚本规模、GUI/JASS/Lua、保护状态、自定义对象和导入资源 |
| 验证与修复 | 已知问题、可复现缺陷、需要回归的流程和版本矩阵 |
| 工具与发布 | 构建工具改动、资源许可清理、说明和可重复构建 |

按工作包记录主要差异、粗粒度工时区间、依据和关键假设即可；风险较高或两条路线接近时，再扩展为乐观/最可能/悲观三点估算。未知工作不能按 0 计。关键文件无法合法取得、许可不允许改编/分发，或地图受保护无法审计时，该路线应标记为“不可行”，不再继续下载其他明显不合适的作品来凑比较对象。

若两条路线的合理工时区间重叠，或结论取决于一个尚未验证的关键假设，应先做范围受限的只读检查或技术试验，再重新估算。没有近似候选时，记录社区路线不成立并评估官方原图路线，不需要虚构双方工时对比。
