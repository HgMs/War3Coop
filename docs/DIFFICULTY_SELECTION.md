# 难度选择与原版机制对接

## 已决定方案

独立多人地图不依赖自定义游戏大厅设置战役难度。进入地图后，由原版单人战役中原本由真人控制的可玩槽位选择本局难度。

这里的“原版真人槽”指官方原图中控制器为 `User` 的原可玩阵营，不表示人族种族，也不等同于创建房间的房主。转换为合作地图后，该槽位及其玩家编号应按单关 `ORIGINAL_COOP_MECHANICS.md` 的槽位盘点确定，不得统一写死为 `Player(0)`。

开局选择只提供原版战役初始可选的两档：

| 显示名称 | 引擎值 |
| --- | --- |
| 普通 | `MAP_DIFFICULTY_NORMAL` |
| 困难 | `MAP_DIFFICULTY_HARD` |

`MAP_DIFFICULTY_EASY` 继续作为引擎和原版脚本能够识别的内部档位，但不显示为开局选项。是否实现“普通难度失败后降低为简单并重开”属于独立的多人失败/重开机制，必须另行决定，不能直接沿用只为单人流程提供的失败对话框。

## 启动顺序

难度选择必须发生在任何原版初始化逻辑读取难度之前：

1. 完成显示选择器所必需的地图基础初始化，并阻止玩家单位、电脑单位和原版事件提前开始活动。
2. `main` 只安排一次性启动入口并返回；在经典客户端中通过 0 秒或极短的一次性计时器于 `main` 返回后创建和显示选择器，不在 `main` 内直接依赖 UI 可见性。
3. 只向原版真人槽显示可操作的普通/困难选择器；其他真人玩家只收到等待状态。
4. 在同步的选择事件中调用 `SetGameDifficulty(MAP_DIFFICULTY_NORMAL)` 或 `SetGameDifficulty(MAP_DIFFICULTY_HARD)`。
5. 记录本局已经完成选择，关闭等待界面并恢复控制。
6. 之后才初始化和执行原版触发器、难度分支、AI、计时器及开场过场。

不得仅把异步对话框加入普通“地图初始化”触发器后便继续执行其他初始化触发器。选择完成前，任何一次性的单位增删、玩家 handicap、资源、升级、波次、计时器或 AI 启动都不得读取默认难度并提前生效。

经典 JASS 不允许把“结构解析成功”当作最低版本可编译的证据。难度完成函数若调用初始化助手，这些助手必须在调用点之前声明；生成后的完整脚本必须使用最低目标版本的 `common.j`、`Blizzard.j` 和兼容编译器做语义检查。

## 原版机制对接

选择结果以引擎的 `GameDifficulty` 为唯一事实来源。原版脚本中已有的 `GetGameDifficulty()` 与 `MAP_DIFFICULTY_NORMAL` / `MAP_DIFFICULTY_HARD` 比较应优先原样保留，不为每关另建一套平行难度变量。

每关实现前仍须审计并记录：

- 所有 `GetGameDifficulty()`、`GetDefaultDifficulty()`、`SetGameDifficulty()` 和 `SetDefaultDifficulty()` 调用；
- 初始化阶段按难度执行的单位增删、handicap、资源、科技、升级、波次与计时器；
- 在 `StartCampaignAI` 前后读取难度的地图脚本和 AI 脚本；
- 从战役缓存、游戏缓存或自定义变量读取或保存难度的逻辑；
- 失败、重开、载入下一关时可能修改或重置难度的逻辑。

独立多人地图不得使用 `SetDefaultDifficulty` 修改玩家的战役档案默认值。任何影响同步游戏状态的难度设置与后续初始化都不得放在 `GetLocalPlayer()` 分支中。

## 异常兜底

- 选择流程超时、未响应或失效时，本局采用普通难度并继续初始化，不能永久卡在等待状态。
- 选择结果只允许提交一次；超时和按钮事件同时到达时，后续入口不得重复初始化原版触发器或 AI。
- 具体等待时长可由公共实现统一确定；无论时长为何，选择界面必须明确显示普通难度是兜底值。

## 验收要求

- 普通和困难分别开局时，`GetGameDifficulty()` 返回对应引擎值。
- 只有原版真人槽能够提交选择，其他合作玩家不能改变结果。
- 选择前没有原版任务、过场、AI、波次或难度相关一次性动作提前执行。
- 选择后所有原版难度分支只执行一次，并沿用该关原版的普通或困难行为。
- `main` 返回后选择界面才显示，且生成脚本在最低目标版本通过完整语义编译，不存在函数向后引用。
- 原版真人槽未响应或选择流程超时时能够按普通难度继续，且不会重复初始化。
- 在 1.24e 与 1.31 的联机测试中，两名玩家观察到相同难度、任务状态、单位状态和 AI 行为，且无不同步。
